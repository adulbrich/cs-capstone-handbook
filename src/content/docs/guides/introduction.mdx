The guides are the engineering handbook inside the handbook: opinionated, concrete references for how to run a real software project. Each one explains a practice and the reasons for it, with sources, so you can adapt it to your project instead of following it step by step. Reach for a guide when your team hits the problem it covers, or better, one sprint before.

## Working Together

- [Working Agreement](/guides/working-agreement/): what the agreement settles (roles, decisions, communication, AI tool norms), how to write it together, and how to keep it current.
- [Sprint](/guides/sprint/): how a two-week sprint runs from planning to retrospective, what "done" has to mean, estimating and protecting the plan, and when Kanban fits better.
- [Planning and Prioritization](/guides/planning/): ideation techniques, prioritization methods, and how to pick a success metric you can actually measure.
- [Retrospectives](/guides/retrospectives/): formats and facilitation for sprint, milestone, and project retrospectives, and the post-mortem after an incident.
- [Conflict and Performance Conversations](/guides/conflict/): conflict-handling modes, raising a contribution problem, and when to escalate.

## Building

- [Git and GitHub](/guides/git-and-github/): a branching workflow, the pull request cycle from branch to merge, merge conflicts, and the repository settings that enforce the workflow.
- [Requirements](/guides/requirements/): writing testable requirements for your repo's living `docs/requirements.md`.
- [Technical Design](/guides/technical-design/): what `docs/design.md` has to decide (architecture, interfaces, data), spikes for the risky parts, design review, and keeping the document true as the code moves.
- [ADR](/guides/adr/): which decisions deserve an architecture decision record, what goes in one, and how to review, store, and replace it.
- [Generative AI](/guides/generative-ai/): where to spend your attention, what makes delegating the rest reasonable, what not to paste into a tool, and what the research says about how much these tools help.
- [AI Project Setup](/guides/ai-project-setup/): `AGENTS.md` and its per-tool equivalents, hooks and gates, MCP servers, and skills, all checked into the repository.

## Verifying and Shipping

- [Testing Strategy](/guides/testing-strategy/): the pyramid, contracts, and what to test when time is short.
- [Accessibility Testing](/guides/accessibility/): the automated gates, the keyboard and screen-reader pass, and testing with a daily assistive-technology user.
- [Security](/guides/security/): STRIDE, secrets, dependencies, and managed auth.
- [DevOps](/guides/devops/): CI/CD, environments, deployment platforms, and rollbacks.
- [Shipping](/guides/shipping/): how to measure shipped, four common kinds of project worked through it, and the external clocks each one has to start early.
- [Documentation](/guides/documentation/): which documents to write for which reader, from the README to the API reference, and how to keep them accurate as the code changes.

## Communicating

- [Presentations](/guides/presentations/): sprint demos, stakeholder presentations, design reviews, and public demonstrations such as a showcase or a conference demo.
